# A02 — Freshness Metadata Forgery Corrective Validation

## Original Weakness

The original V3 decision engine trusted the source-provided freshness label:

`source_freshness = current`

without independently validating when the evidence was actually observed.

During adversarial test A02, stale evidence dated:

`2025-01-01T00:00:00Z`

was labeled current and incorrectly received:

- Decision confidence: `HIGH`
- Evidence trust: `TRUSTED`
- Recommendation: `DISABLE`
- Authority: `AUTO_REMEDIATE`

The failure was preserved before correction.

## Corrective Control

V3 now requires secondary identity evidence to include:

`observed_at_utc`

The engine independently parses the observation timestamp and calculates evidence age.

The maximum permitted secondary evidence age for unattended destructive authority is:

`24 hours`

The engine now enforces:

`declared current + stale observation timestamp -> STALE`

and:

`STALE -> REQUIRE_APPROVAL`

Missing, invalid, or future observation timestamps are also prevented from receiving trusted unattended authority.

## Canonical Dataset Update

The trusted secondary identity dataset was updated with observation timestamps.

Current secondary records use:

`2026-10-16T15:00:00Z`

The intentionally stale `ingest.bridge` record uses:

`2026-01-01T00:00:00Z`

## Result

**PASS — FRESHNESS METADATA FORGERY BLOCKED**

V3 no longer accepts a source-provided `current` label as sufficient proof of freshness.

Evidence age is now independently calculated from the observation timestamp before destructive authority is assigned.

## Security Boundary

The corrected authority rule is:

`fresh label + stale timestamp -> STALE evidence`

and:

`STALE evidence -> no AUTO_REMEDIATE`

This prevents stale secondary evidence from independently authorizing unattended destructive remediation.

## Production Requirement

Production evidence providers must:

1. provide a trustworthy observation timestamp;
2. refresh evidence within the defined freshness window;
3. prevent unauthorized timestamp modification;
4. ensure timestamps are generated by the evidence-producing system rather than the remediation engine;
5. treat missing, malformed, stale, or future timestamps as insufficient for unattended destructive action.
